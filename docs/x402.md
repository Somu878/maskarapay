# x402 payments in MaskaraPay

`POST /api/v1/redact` can be monetized with [x402](https://www.x402.org/), the
HTTP-native "402 Payment Required" micropayment protocol built around USDC on
Base. It works like the web's original status code intended: when you ask the
server for redaction and it wants payment, it answers `402` with a machine-readable
price and payee; your client builds and signs a USDC charge locally and retries the
same request with the signed payment attached; a facilitator service verifies that
signature, pulls the USDC on-chain, and returns a settlement receipt that the server
forwards to you alongside the actual redaction result. MaskaraPay speaks the current
protocol version **v2** (challenge in the base64 `PAYMENT-REQUIRED` response header,
payment in `PAYMENT-SIGNATURE`, receipt in `PAYMENT-RESPONSE`) and the legacy
**v1** dialect (challenge in the 402 body, payment in `X-PAYMENT`, receipt in
`X-PAYMENT-RESPONSE`) so old clients keep working.

## Flow

```
 Client                      MaskaraPay server                     Facilitator
   |     POST /api/v1/redact          |                                |
   |--------------------------------->|                                |
   |  402 + payment requirements      |                                |
   |  (v2: PAYMENT-REQUIRED header,   |                                |
   |   v1: 402 body)                  |                                |
   |<---------------------------------|                                |
   |  build EIP-712 EIP-3009          |                                |
   |  USDC transferWithAuthorization  |                                |
   |  retry POST + payment header     |   POST /verify                 |
   |  (v2: PAYMENT-SIGNATURE,         |------------------------------->|
   |   v1: X-PAYMENT)                 |  {isValid:true, payer:...}     |
   |--------------------------------->|<-------------------------------|
   |                                  |   POST /settle (on-chain)      |
   |                                  |------------------------------->|
   |                                  |  {success, transaction,...}    |
   |                                  |<-------------------------------|
   |  200 + settlement header         |                                |
   |  (v2: PAYMENT-RESPONSE,          |                                |
   |   v1: X-PAYMENT-RESPONSE)        |                                |
   |<---------------------------------|                                |
```

Funds move **before** inference runs (settle-first, see
[Security notes](#security-notes)).

## MaskaraPay environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `MASKARA_PAYEE_ADDRESS` | unset | Payee EVM address. Unset → payments disabled, all requests pass through free. |
| `MASKARA_PRICE_USD` | `0.01` | Price per request in USD, converted to USDC atomic units (6 decimals; `"0.01"` → `"10000"`). |
| `MASKARA_X402_NETWORK` | `base-sepolia` | Settlement chain: `base-sepolia` (testnet) or `base` (mainnet). |
| `MASKARA_FACILITATOR_URL` | `https://x402.org/facilitator` | Facilitator base URL used for `POST /verify` and `POST /settle`. |
| `MASKARA_FACILITATOR_AUTH` | unset | Optional `user:secret` basic-auth credentials for the facilitator (e.g. Coinbase CDP). |
| `MASKARA_RESOURCE_URL` | `http://<bind_addr>/api/v1/redact` | Resource URL advertised in 402 challenges; set this to the public URL when tunneling. |

## End-to-end locally with the mock facilitator

Three terminals. Terminal 1 — start the stateless mock facilitator
(stdlib-only, no signature checks, no real funds):

```bash
python3 scripts/x402/mock_facilitator.py
# mock x402 facilitator on http://127.0.0.1:8899
```

Terminal 2 — run the server with payments enabled, pointed at the mock:

```bash
cd service
MASKARA_PAYEE_ADDRESS=0x209693Bc6afc0C5328bA36FaF03C514EF312287C \
MASKARA_FACILITATOR_URL=http://127.0.0.1:8899 \
cargo run --release
```

Terminal 3 — install the client's two dependencies in a throwaway venv and run
it. The client will exercise **both** protocol versions by default:

```bash
python3 -m venv /tmp/x402-dev-venv
/tmp/x402-dev-venv/bin/pip install -r scripts/x402/requirements.txt
export MASKARA_PRIVATE_KEY=0x...   # any funded-or-unfunded test key; never commit
/tmp/x402-dev-venv/bin/python scripts/x402/pay_client.py http://127.0.0.1:8080
```

Expected client output (abridged, one run per protocol version):

```
[x402] payer 0x2076...cA56
--- x402 protocol version 2 ---
[x402] POST http://127.0.0.1:8080/api/v1/redact -> 402 Payment Required
[x402] offer: scheme=exact network=eip155:84532 price=$0.010000 (10000 USDC atomic units)
[x402] payTo=0x209693Bc6afc0C5328bA36FaF03C514EF312287C asset=0x036CbD53842c5426634e7929541eC2318f3dCF7e maxTimeoutSeconds=60
[x402] retry with PAYMENT-SIGNATURE -> 200 OK
[x402] settlement: success=true transaction=0x1b0f...e29a network=eip155:84532 payer=0x2076...cA56
[x402] redacted_text: 'Email [EMAIL] about the invoice.'
```

Expected facilitator stderr:

```
POST /verify 200
POST /settle 200
```

Right after the request, the mock facilitator also prints a `GET /supported`,
`POST /verify`, `POST /settle` trail — if you see no `POST /settle` the server
gating isn't active (check `MASKARA_PAYEE_ADDRESS`). To force failure paths,
restart the mock with `MOCK_VERIFY_FAIL=1` (server responds `500
facilitator_unavailable`-style failures) or `MOCK_SETTLE_FAIL=1` (client sees a
failure receipt and exits nonzero without a result).

## Real testnet walkthrough (Base Sepolia)

1. Get a throwaway wallet key (any EVM key, e.g. from `python -c
   "import secrets;print('0x'+secrets.token_hex(32))"`). This key **is your
   money** on mainnet — for now use it only on testnet.
2. Fund that address with Base Sepolia USDC through Circle's faucet:
   <https://faucet.circle.com/>. EIP-3009 `transferWithAuthorization` does not
   require you to pay gas yourself, so testnet USDC alone is enough.
3. Run the server with the **default** facilitator
   (`MASKARA_FACILITATOR_URL` unset → `https://x402.org/facilitator`, free and
   testnet-only; no auth needed on testnet):

   ```bash
   cd service
   MASKARA_PAYEE_ADDRESS=0x209693Bc6afc0C5328bA36FaF03C514EF312287C cargo run --release
   ```

4. Run the client with `--network base-sepolia` (default):

   ```bash
   MASKARA_PRIVATE_KEY=0x... \
     /tmp/x402-dev-venv/bin/python scripts/x402/pay_client.py http://127.0.0.1:8080 --version 2
   ```

   Keep the key in the shell environment (or a `.env` file you never commit) —
   **never** hard-code it in scripts, docs, or the repo.

If no USDC lands from the faucet, the x402.org testnet facilitator is free and
rate-limited; mock mode above is the zero-dependency alternative.

## Mainnet and higher prices

- Gateway facilitator: Coinbase Developer Platform (CDP) requires basic auth.
  Set `MASKARA_FACILITATOR_URL` and `MASKARA_FACILITATOR_AUTH=user:secret`
  accordingly; MaskaraPay forwards these credentials with every verify/settle
  call. The public x402.org facilitator is **testnet-only**.
- Prices: `MASKARA_PRICE_USD` feeds the USDC atomic-amount conversion (6
  decimals). Raise it only after you trust your facilitator and monitor
  receipts.
- Asset + domain constants (already baked into the client; the server sends
  them in each challenge):

  | Network | `MASKARA_X402_NETWORK` | Chain id | USDC contract | EIP-712 domain name / version |
  | --- | --- | --- | --- | --- |
  | Base Sepolia | `base-sepolia` | `84532` | `0x036CbD53842c5426634e7929541eC2318f3dCF7e` | `USDC` / `2` |
  | Base mainnet | `base` | `8453` | `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` | `USD Coin` / `2` |

  Note the domain name differs on mainnet (`USD Coin`, not `USDC`) — clients
  must sign with the correct deployed-token domain or verification rejects the
  signature.

## Payload reference (for the server builder and other clients)

v2 402 challenge (`PAYMENT-REQUIRED` header, base64 JSON):

```json
{
  "x402Version": 2,
  "error": "",
  "resource": { "url": "http://127.0.0.1:8080/api/v1/redact", "description": "", "mimeType": "application/json" },
  "accepts": [
    {
      "scheme": "exact", "network": "eip155:84532", "amount": "10000",
      "asset": "0x036CbD53842c5426634e7929541eC2318f3dCF7e",
      "payTo": "0x209693Bc6afc0C5328bA36FaF03C514EF312287C",
      "maxTimeoutSeconds": 60, "extra": { "name": "USDC", "version": "2" }
    }
  ]
}
```

v2 payment (`PAYMENT-SIGNATURE` header, base64 JSON) and v1 payment
(`X-PAYMENT`, same inner shape, looser envelope):

```json
{
  "x402Version": 2,
  "resource": { "url": "http://127.0.0.1:8080/api/v1/redact", "description": "", "mimeType": "application/json" },
  "accepted": { "scheme": "exact", "network": "eip155:84532", "amount": "10000", "asset": "0x036C...", "payTo": "0x2096...", "maxTimeoutSeconds": 60, "extra": { "name": "USDC", "version": "2" } },
  "payload": {
    "signature": "0x<65-byte hex>",
    "authorization": {
      "from": "0x...", "to": "0x...",
      "value": "10000",
      "validAfter": "1761000000", "validBefore": "1761000360",
      "nonce": "0x<32-byte hex>"
    }
  }
}
```

v1: `{"x402Version":1,"scheme":"exact","network":"base-sepolia","payload":{...}}`
with 402-body requirements carrying `maxAmountRequired` instead of `amount` and
CAIP-2 ids replaced by plain network names.

Settlement receipts (`PAYMENT-RESPONSE` / `X-PAYMENT-RESPONSE`, base64 JSON):
`{"success":true,"transaction":"0x...","network":"eip155:84532","payer":"0x..."}`;
on failure `transaction` is `""` plus `errorReason`.

Signing is EIP-712 `TransferWithAuthorization` with fields
`from(address), to(address), value(uint256), validAfter(uint48),
validBefore(uint48), nonce(bytes32)` over a domain
`{name,version,chainId,verifyingContract}` per the table above.

## Raw 402 with curl

```bash
curl -sS -D /tmp/x402-headers.txt \
  http://127.0.0.1:8080/api/v1/redact \
  -H 'content-type: application/json' \
  --data '{"model":"somukandula/maskara","text":"Email ravi.sharma@example.com about the invoice."}' \
  -o /tmp/x402-402.json && cat /tmp/x402-headers.txt
# -> HTTP/1.1 402
# -> payment-required: eyJ4NDAyVmVyc2lvbiI6Mi4uLg==
```

Decode the v2 challenge (jq-friendly):

```bash
awk 'tolower($0) ~ /^payment-required:/ {sub(/^[^:]*:[ ]*/,""); print}' /tmp/x402-headers.txt \
  | tr -d '\r' \
  | python3 -c 'import sys,json,base64;print(json.dumps(json.loads(base64.b64decode(sys.stdin.read().strip())),indent=2))'
```

(v1 needs no decoding — the 402 body itself is the challenge: `jq . /tmp/x402-402.json`.)

## Security notes

- **Settle-before-serve**: the server settles payment *before* running
  inference. Funds move even if inference later fails — that cost is
  documented, accepted behavior; there is currently **no refund flow**.
- **Replay protection**: the server caches the nonce of every payment that
  passed verification and went to settlement (kept ~10 minutes past the
  authorization's own expiry). Replaying the exact same signed payload gets
  a `402` with error `payment_already_used` and no facilitator round trip —
  no duplicate charge, and no free result for a client that lost a paid
  response. The cache is in-memory and per-process; restarting the server
  clears it.
- **Facilitator outage**: if verify/settle can't be reached or fails, the
  server answers `500 facilitator_unavailable` — no redaction, no charge, but
  also no fallback free tier.
- **Keys**: only ever keep `MASKARA_PRIVATE_KEY` in the environment (or an
  ignored `.env`). Never commit keys to this repo; the client script prints
  only signatures and addresses, never key bytes.
- The mock facilitator is permissive by design and must never be reachable
  from outside your machine.
